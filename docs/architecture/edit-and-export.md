# Edit timeline rendering and export

This document owns the application-lifetime edit workspace, decoder/render ownership, playback pacing and export transaction. The [product specification](../product-spec.md#8-recording-lifecycle) owns the workspace and interaction contract.

## Separate playback from export

Edit is a resident top-level page. Its C++ workspace owns assets, typed video/audio tracks, linked clips, selection and playhead independently of QML. Imported files remain in place. Navigation pauses playback and retains the workspace; application exit discards it because project persistence is not implemented. Completed recordings reuse retained masters where available. Split recordings add ordered segment assets. Unavailable segments with known duration retain their intervals. Segments whose duration cannot be probed remain in Media with an explicit warning and are not placed on the timeline.

A finalized MKV master is available for explicit editing while MP4 delivery continues. The editor holds a source lease, so retention defers its rename until the reader can release the path. MP4 remains pending until publication finishes. Opening the master does not create a successful History entry.

Pressing Export commits an immutable snapshot to an independent operation. Leaving Edit does not cancel that operation. Its completion/failure reaches notifications. Eligible stream copy does not depend on successful preview decoding, GPU presentation or audio playback. Crossfade rendering uses the same timeline evaluator, source reader and GPU compositor as preview.

A decode failure therefore leaves an honest Preview unavailable/Timeline previews unavailable state while preserving any valid trim/export operations. It must not be reported as corruption of the source merely because one preview decoder could not open it.

Source-open readiness is separate from frame presentation. A seek can supersede the original open generation while retaining its decoder or render reader. Successful access republishes source readiness for the current generation; only the scene-graph handoff acknowledges presentation. Stale open results cannot mark a replaced source ready.

Queued workspace updates retain the newest revision within each playback-command interval.
Dispatching a seek, transport, monitoring or lifecycle command seals the preceding interval, so a newer revision cannot replace the workspace that command must observe.
Only preview work is superseded; workspace commands and undo history remain intact.

The GUI owns requested transport intent separately from acknowledged worker playback. Each seek or transport request carries a command ID and preview generation. Only matching state, completion, position and end replies may update the current transport. Obsolete queued transport requests yield before decoder work. Ordinary seeking preserves requested playback, whereas explicit frame inspection pauses first. Scrubbing temporarily quiesces playback without replacing intent, so a later explicit Pause cannot be undone by scrub release.

The non-composited player can retain its session across edits and split segments when the asset, validated source fingerprint, video stream and file size/write time remain compatible.
It updates the source-to-timeline offset rather than treating a new clip ID as a new source.
Changing that callback mapping first pauses playback and joins any outstanding scrub read.
An unchanged mapping retains the asynchronous newest-pending seek behavior.
Monitoring revisions are applied once per session. Gaps, unavailable sources and transitions between simple playback and composition reset the raw source binding.
Simultaneous composition contributions keep their independent decoder cursors.

## Decoder ownership and queues

There are three workers: demux, video decode, and audio decode/resample. The demux worker exclusively owns its `AVFormatContext`; each decoder owns its codec context. No FFmpeg context is concurrently manipulated by multiple workers.

Demux reads against the playback clock up to approximately one second ahead. Packet-queue occupancy alone is not the pacing clock: container interleaving can put an audio packet behind a blocked video packet and starve audio. Per-stream queues have soft one-second and hard eight-second/8192-packet bounds. A stream can exceed its soft bound while the peer is below its low-water mark; the hard bound still prevents unbounded growth.

Audio output is paced by the WASAPI render ring, which can block only the audio worker. Video has no separate bounded decoded-frame queue. A newest-wins mailbox carries the latest decoded frame, and the presentation gate drops late frames before GPU conversion. Under sustained overload the decoder can skip nonreference pictures and restore normal decoding when it catches up.

## Playback clock and multiple audio tracks

Externally clocked raw-video playback selects disabled source-audio decode explicitly. This bypasses source monitoring admission without confirming any tracks and creates no source-audio queues or resamplers. Legacy source playback retains its monitoring guard. Timeline preview admission instead follows authored enabled contributions, so an unresolved alternative mix cannot disable video or already admitted timeline audio. Raw and composed preview share timeline audio startup and its silent wall-clock fallback when no output endpoint can initialize.

The master clock is the endpoint's actual play cursor (`IAudioClock`), not the number of samples written into a render buffer. Stop/reset flushes the endpoint so clock and queued playback agree. A caller asks whether audio is **delivering**, not merely whether the file declares an audio stream.

Timeline preview evaluates authored audio through the shared timeline reader independently of video composition. Clip gain, mute, deletion and source-time placement therefore apply even when an opaque video uses the reusable raw-source session. That session emits no source audio and follows an external source-time clock derived from the timeline clock. The session samples the callback only on its owner thread and publishes an atomic clock for the decode threads. Pause joins video playback before the worker stops or destroys the timeline audio queue. Video cuts and gaps replace only the raw-source binding, retaining the timeline audio queue and its origin. Audio evaluation does not require SDR video admission, so this separation preserves raw HDR playback. If direct playback cannot initialize its audio endpoint, it retains the existing silent wall-clock fallback.

File-only playback inspects and independently decodes every audio stream where possible. It sums tracks with soft limiting, not division by track count, so a single active track keeps its level. This is intentionally different from the recording mixer's configured-source weighting. A failed file-only audio decoder/resampler can be omitted while the remaining tracks continue. Timeline preview and rendered export instead fail explicitly when an enabled contribution cannot be decoded. An audio-track description still answers what the file carries, not only what decoded successfully.

A file with no delivering audio uses the supported wall-clock fallback rather than waiting for an audio cursor that cannot advance. Seeking resets the applicable queues, clock origin and decoder state together. Frames decoded for an earlier generation must not appear after a newer seek.

## Decoded frame representation

The video worker passes a refcounted `AVFrame` through `RawDecodedVideoFrame`: planar pointers and strides, `Yuv420P8`, `Yuv420P10` or `Yuv444P8`, range, matrix, primaries, transfer and a PQ-source flag. The backing shared pointer with the `av_frame_free` deleter is the cross-thread lifetime owner. A borrowed plane pointer must not outlive it. Explicit transfer metadata is required for linear-light rendering; a BT.709 matrix does not establish a BT.709 transfer function.

Interactive color conversion runs on the GPU using the caller's D3D11 device/context. CPU reference conversions remain test oracles, not a second interactive conversion policy. Qt imports the converted texture into a scene-graph image node; no child player HWND exists.

The presentation gate runs before upload/conversion. Converting every high-frame-rate source picture when the endpoint/display clock will discard most of them wastes GPU work and can itself cause audio/video contention.

## Keyboard and pointer arbitration

`EditInteractionController` owns one Space reservation independently of transport state.
QML offers it only unhandled, unmodified key presses after control input handling.
One event filter on the owning Quick window observes release, repeat, pointer consumption and cancellation.
A genuine unconsumed release emits the same transport toggle as the Play button.
Focus changes, window deactivation, hiding, Escape, other keys and an existing clip gesture suppress delayed toggles.

QML owns the temporary canvas-only pointer grab and passes scene coordinates to the controller.
Panning emits incremental horizontal deltas into the bounded viewport, advancing the pointer anchor even at a viewport limit.
Space release or cancellation stops movement without surrendering a captured pointer before its release.
This prevents a terminating pan from becoming a seek, selection or clip edit.
The controller detaches scope/window subscriptions and its event filter before destruction.

## Hardware decode boundary

Open attempts D3D11VA hardware decoding without a vendor-specific preference. Failed device creation or unsupported stream negotiation falls back to software at open. There is no arbitrary mid-stream hardware/software switch.

This path is not zero-copy. Hardware frames are read back using `av_hwframe_transfer_data`, deinterleaved and passed through the same plane-based converter. FFmpeg owns the decoder device and does not supply the Record preview's shared NT-handle transport. A future GPU-native decoder/renderer path needs its own explicit device/surface ownership contract.

P010 hardware readback is left-justified. Internal ten-bit planar samples are not: shift each value by six bits while deinterleaving. This path is used by both interactive playback and the separate thumbnail decoder, so neither may assume the other already performed the conversion.

## Timeline and export transaction

`EditSessionAdapter` exposes the typed workspace to QML. Workspace commands validate a candidate before publishing it. Rejected and successful no-op commands preserve IDs, history and revision. Applied commands and undo/redo advance a monotonic revision. Immutable metadata snapshots can be retained outside the UI thread. Undo keeps metadata deltas under a 64 MiB budget and evicts complete oldest entries, retaining shared source descriptors rather than copying media.

Time is signed 64-bit microseconds, with a checked rational output frame grid. Clip move, trim, drag, nudge, visible-row queries, asset insertion, recording imports and transport positioning accept microseconds directly. Background import and history requests retain their original placement through probing. Crossfade drop matching compares exact cut times. The millisecond adapter entry points validate conversion bounds and delegate to those precise operations. Result range, playhead and selection are separate values. Ripple deletion removes the union of selected intervals once and maps the result range through that union. If a surviving clip would straddle removed time or the resulting geometry violates a track constraint, the whole command is rejected. Group moves can create destination tracks in the same transaction. Per-stream clips retain validated source identity and global container index separately from track identity. Initial import enablement is retained separately from authored mute/gain state for original-copy assessment.

Timeline edits are not keyframe-limited. Snapping uses a screen-pixel tolerance capped at 250 ms and only changes the candidate being moved or trimmed. Ripple editing starts off, and ordinary trim preserves suffix positions. Delete and Shift+Delete retain their fixed lift/ripple meanings independently of that toggle. The adapter freezes a workspace snapshot at gesture start, builds the complete command and calls `PreviewEdit` for each candidate. A changed workspace revision cancels the frozen gesture before its QML delegates are replaced. QML retains committed geometry beneath separate visible candidate ghosts. Release applies that exact command at the frozen revision, so invalid/stale candidates cannot add partial edits or history. New tracks belong to the same transaction. Gap closure has a separate whole-timeline preview and refuses to cut contributions on another layer. Spacers are source-free metadata, included in snapshots and undo deltas but omitted from media contribution evaluation. Fixed timeline end is separate undoable state and extends on later material without shrinking on deletion.

Track geometry belongs to a session-owned presentation model keyed by stable track IDs. Base rows drive hit and drop testing; candidate rows inherit resident heights for preview rendering without changing those base targets. Labels, clips, spacers, junctions and ghosts consume the same geometry. Rows have an 18 px header and at least 10 px of content, with height bounded to 28..240 px. Clip surfaces fill their rows. Minimum-height rows retain their name and media icon and do not request new previews. Closing the workspace clears remembered heights before entity IDs can be reused; ordinary removal and undo retain them.

QML creates clip delegates and adaptive ruler ticks only for the visible time interval. Visible clips come from a keyed C++ row model: an edit, a selection change or a scroll updates, moves, inserts or removes rows by clip id, so a clip that stays in view keeps its delegate. A delegate re-requests thumbnail tiles or its waveform only when the source, visible source window or preview-body visibility changes, because a new request recreates every tile image. The C++ viewport owns the visible microsecond interval and pixel scale. QML reads an immutable mapping value through a notified property, so coordinate bindings observe both origin and scale changes. Clip, spacer and junction rectangles are bounded by the viewport rather than the source duration. Clipped boundaries do not acquire trim handles. Horizontal scrolling moves the visible interval without allocating a duration-wide Flickable. Fit covers zero through the timeline end and follows viewport resizing. Pointer-anchored wheel zoom and playhead-anchored keyboard zoom share the mapping. Boundary actions preserve Previous View when they do not change the visible interval. Left/Right use the checked rational output grid, and I/O boundaries retain microseconds instead of rounding through their millisecond labels. This grid does not identify individual VFR source frames.

`EditTimelineAdapter` owns one waveform service and the existing thumbnail source/broker. Clip rows carry verified content identity and container-stream mapping from immutable import descriptors. Waveform requests deduplicate by content, stream identity/mapping and schema; min/max/RMS pyramids remain in source time. Verified recording audio retains its declared stream identity in cache keys. Foreign audio uses content identity and the global container stream index, excluding the temporary monitoring UUID assigned on each import so reopening unchanged media reuses the cache. Path resolution captures registration identity and content fingerprint together before probing file aliases outside broker locks. The worker retains that fingerprint for open-time byte validation even if the registry changes during probing. Eligible visible decodes precede speculative prefetch jobs. Thumbnail keys add source timestamp, size variant and rendering schema, with source-anchored tile grids and bounded visible prefetch. Thumbnail request epochs advance when cache clearing finishes or the worker detaches. Retired requests complete once outside broker locks. Their completions and parked jobs cannot consume later requests, and clearing retains source registrations. The OS application cache holds atomic, hashed, versioned artifacts under 512 MiB waveform and 1 GiB thumbnail disk LRUs. Decoded thumbnail RAM is bounded to 16 MiB and immutable waveform blocks to 32 MiB, including consumer-pinned blocks after eviction or cache clear. Waveform analysis has a separate 64 MiB buffer admission limit. One audio-only sequential cursor retains decoder and resampler state across adjacent chunks. A streaming hierarchy retains one pending child and a 2048-bucket write buffer per level, bounded to 40 levels, instead of the full pyramid. Only the background worker accesses waveform staging, disk layouts and source availability. It publishes immutable 256-bucket blocks with exact valid sample coverage and a cache generation after each analysis chunk. Render reads return shared memory snapshots or an unavailable result and enqueue missing interest without storage access. Staging writes, finalization and reads never hold the renderer-shared metadata lock. The software renderer allocates only the visible clipped raster, and native geometry retains source-anchored blocks across pans. Normalized PCM detail is exposed through a separate worker-owned cursor and immutable ticketed snapshots. It does not seek the overview analyzer or player. Cache keys retain exact source sample windows independently of view generations. Each window is limited to 4 MiB, with a 16 MiB PCM sublimit inside the combined 32 MiB waveform data budget. Admission includes decode scratch, in-flight publication and consumer-pinned results after eviction or clear. Decoder internal workspace remains separately bounded by the engine read contract. Live tickets retain Ready data until retirement. Retiring the last ticket cancels source opening, and job/cache generations reject obsolete completions. The waveform item subscribes on the GUI thread and renders only immutable snapshots during scene-graph synchronization. Detail uses source-aligned 4096-sample windows when the finest peak bucket exceeds a pixel and the visible interval contains at most 8192 samples. It includes one successor sample for continuous interpolation at window boundaries. Larger intervals retain the peak overview. Native detail geometry is reused across pans; software detail uses the same clipped raster bound as peaks. Ancestor geometry, clipping and visibility changes retire interests that leave view. Source cancellation and cache clear invalidate tickets explicitly. Memory-pressure retries are coalesced to at most one attempt per second per active item; missing coverage never enters that retry loop. Actual decoded sample spans exclude synthesized gap/tail padding. Missing coverage is unavailable, and nonfinite samples fail without entering the cache. The source-rate conversion uses the same normalized origin and resampling path as timeline evaluation. Finalization hashes the compatible level-major payload in 64 KiB chunks before atomic publication. Staging reservations are bounded to one disk budget in addition to published entries; abort and clear invalidate writers and remove their staging files. Normalization changes version the source key independently of the payload schema. Waveform and thumbnail workers compare the leased open source bytes against the expected content SHA before decoding. Warm cache reads avoid decoder work. Windows background mode lowers CPU/I/O priority, and foreground playback, seeking, recording and export pause analysis between bounded chunks. A generation barrier prevents jobs from republishing cleared thumbnail data. Image responses revoke their callback receiver before cancelling tickets, so decoder completion cannot target a destroyed QML response. Cache validity never overrides missing-source or content-identity checks. Details exposes an explicit combined clear action.

Finished export freezes Entire Timeline, Occupied Content, I/O/result range or selected clip IDs into its plan. Occupied and selected bounds retain interior gaps and rebase output at the selected start. Selected IDs never pull in unrelated simultaneous tracks, and partial junction ownership is blocking. Source validation, leases, audio lineage and decoder access use the same enabled contributions intersecting the frozen span; inactive junction endpoints may remain as envelope metadata without opening their sources. Original-stream compatibility additionally checks every actual source stream against the complete selected group, preventing an omitted audio clip from reappearing through container copy. A source-free blank output uses retained output geometry/frame rate and opens no media decoder. Older linked imports retain their existing result/entire copy path and must be reimported for the new scopes.

The pure `EvaluateTimeline` function owns half-open intervals, source timestamp mapping, junction progress and canonical curves. It validates same-track overlap geometry and returns ordered video track layers, each with at most a track-local pair, plus audio contributions keyed by stream; zero-weight contributions are omitted. `EvaluateAudioIntervals` partitions a span only at clip, fade and junction boundaries, and `EvaluateAudioGain` evaluates envelopes at absolute 48 kHz sample indices. Both preview and export consume these functions. A single fully opaque visible clip reopens the existing engine session. Junctions, partial opacity, video edge fades and simultaneously visible video clips use `EditTimelineReader`, which keeps one single-owner engine per visible clip and retires the cursors a frame no longer shows before opening new ones. Blank time is a presented black frame for the requested generation and time, never a pending decode, so a seek into a gap converges and playback continues on the wall or audio clock; missing media and decoder failure remain separate degraded states. The item holds one newest-wins frame payload, and request generations reject results from superseded seeks. WASAPI's played-frame cursor drives preview with audio; silent timelines use elapsed time. The decode thread reads up to a second ahead of that clock, and the item's present gate only discards frames the clock has passed, so the single-source session holds each decoded frame until the clock reaches its timestamp. The audio clock is sampled only on the presentation tick, so between samples it is extrapolated by wall time, bounded and not before the device has started playing. Frames are released up to one scheduler tick (16 ms) early so a late timed wake-up does not become a frame the gate drops. Handing frames on as they are decoded shows video ahead of its sound.

Video decoder slots are keyed by clip, including two clips referencing the same asset. Result audio opens one decoder per audio clip, bounded to eight, on that clip's explicit container stream; a source with exactly one audio stream resolves it explicitly, and only a clip without a stream reference over a multi-stream source mixes the confirmed monitoring selection. Mono duplicates to both channels at unity gain, stereo keeps channel identity and other layouts are refused. Each interval is decoded at its own source sample offset and multiplied by the per-sample envelope before the shared brickwall limiter. Audio decode preserves sample continuity across coarse container timestamp ticks and flushes the resampler tail. Preview prebuffers before starting its clock. Timestamped writes discard samples already replaced by endpoint underrun silence, preventing a decode stall from becoming a permanent A/V delay. This does not promise glitch-free audio under overload.

Export acquires immutable read leases for all frozen contributing sources before validating the first identity and retains them through destination publication. Excluded sources require no lease. Splits retain only the original outer fades; cutting inside any linked active fade is rejected atomically because the edge-fade model cannot represent a partial curve on both new clips.

The toolbar offers Match source and a native save dialog rooted in the configured recording output folder. Filename, folder and MKV/MP4 container are user choices; no sibling `_edit` location is imposed. YouTube and Archive profiles remain unavailable. Render output fixes geometry and exact rational frame rate from the first video source before decoding frames. Other dimensions use aspect-preserving Contain into that output.

Per-stream timelines use the export planner. `AssessEditExportFacts` opens the sources to establish which paths actually exist: complete compatible video copy, original-stream copy, exact render and stereo mixing, plus whether the destination aliases a source by file identity. `PrepareEditExport` combines those facts with an immutable `EditExportIntent` (finished result or original streams, an explicit output scope, container) into a frozen plan with independent video and audio paths, typed issues and a hash that binds any boundary consent. `ExecuteEditExport` runs original-stream copy, copied video beside a rendered mix, or full rendering of the planned span. The mix is PCM24 for MKV. For MP4 it is AAC-LC 192 kbit/s written into an intermediate Matroska file, whose packets keep the encoder timestamps with the priming declared as codec delay; the existing faststart remux then turns that delay into a negative first timestamp and an MP4 edit list. AV1 rendering into MP4 is refused. Copied video uses only complete sources that cover the whole timeline from zero, so no removed picture can appear. Requested settings that are unavailable remain requested and block the plan; MP4 is not rewritten to MKV. Timelines from earlier linked imports keep `ClassifyEditExport`, whose eligible single-source trims and compatible full-source concatenations retain the existing stream-copy implementation, including coalesced contiguous splits. That path is keyframe-accurate, not frame-accurate. Native exact PTS/DTS and existing generic-container restrictions remain authoritative.

Every valid same-track overlap owns exactly one junction. Overlaps created by a move or insert receive a full-overlap Crossfade when Auto Crossfade is enabled, or a hard cut when disabled. Changing the toggle leaves existing junctions untouched. A new junction clears the facing edge fades in the same edit. Crossfade defaults to 500 ms. Adding it shifts the incoming linked group and following suffix earlier by its duration. The outgoing group and source-in/out stay unchanged. Removing it converts the junction to a hard cut at its previous midpoint, quantized to the track grid, without moving clips. Custom windows store offsets from the incoming clip start, are clamped to the overlap after geometry changes and collapse to a hard cut at the clamped old midpoint. Time-removal commands retime the stored incoming anchor together with the junction window or cut, so later normalization applies the shift once. A junction disappears with its overlap. Duration is clamped to real clip intervals and neighboring transitions so no three-way overlap exists. These changes are atomic undo commands. Markers map through the resulting clip positions.

`EditTimelineCompositor` reuses the existing plane uploader/YUV converter. Each admitted source has a persistent FP16 working texture holding BT.709-linearized pixels. A track resolves its junction pair with complementary weights, each scaled by that clip's opacity and edge-fade gain, into premultiplied color and coverage. Tracks are then composited back to front with premultiplied source-over into a linear FP16 accumulator, so an upper layer occludes rather than adds and identical pictures keep their level through a Crossfade. A disabled junction endpoint contributes no picture; the remaining endpoint retains its envelope as partial coverage over black or a lower track. Contain letterbox bands carry no coverage and reveal lower tracks. A final pass applies the shared BT.709 output transfer over black. Admission is bounded to eight sources and four UHD frames of summed source pixels. `AssessTimelineVideoAdmission` evaluates that demand before any decoder opens, and export planning refuses an unadmitted span with `ResourceLimitExceeded` instead of failing during encode. A persistent BGRA output feeds presentation or the shared SDR VideoProcessor color setup. Blend/raster/depth/shader state is explicitly established. There is no CPU BGRA blend or readback between layers. Texture sizes are stable until geometry changes, and failed initialization/device removal returns an error.

Render export resolves generic `RecorderConfig` intent and calls `VideoEncoderFactory`/`IVideoEncoder`. One NV12 surface per encoder slot is created and registered once. Acquire/reap/flush and pending-frame completion preserve the encoder's reordered PTS/DTS contract. `IAudioEncoder` uses the shipping PCM24 encoder, and `MatroskaStreamWriter` receives video/audio packets and codec private data. Audio is rounded to the final CFR frame boundary, with an explicit mux duration. Linked imports keep refusing rendered MP4. Per-stream timelines reach MP4 through the AAC profile above; existing lossless MP4 delivery is unchanged.

Recording and Edit render export resolve NVENC preset, tuning and lookahead policy through the same settings helper and `ResolveNvencTuning`. Capability reconciliation uses the selected encoder adapter, and rendering opens that resolved adapter. Explicit presets remain the requested presets when supported.

Unsupported rendering fails closed with a reason. It does not silently tone-map or relabel sources, and does not affect eligible lossless exports.

Valid linked hard-cut timelines use the same render reader when stream copy is ineligible. Copy remains preferred when eligible. Finished-result video copy additionally scans source packets before outcome review, using exact recording timestamp mappings where present and requiring usable PTS/DTS with monotonic timeline decode times. This cancellable pass retains one packet at a time. Unqualified timestamps select the existing render or unsupported outcome instead of failing after a Copy review. OriginalStreams retains its separate single-source remux qualification. Before writing staging media, export prepares an immutable outcome showing the container, codecs and retained or mixed audio tracks. Render uses the explicitly confirmed frozen monitor selection, including deliberate silence. Changed sources, selections or timeline recipes require a new review. Overwrite confirmation is separate from outcome confirmation.

Export writes a sibling temporary and publishes atomically after successful flush/finalization. Overwrite needs explicit confirmation. Cancel enters Cancelling until `QThread::finished` without blocking the UI. Application teardown explicitly requests cancellation and joins the worker before destroying the QML engine or other application services. Adapter destruction also joins, so staging cleanup completes even after the event loop has stopped. The worker captures shared run state and immutable media/configuration values, never the page or adapter. The GUI polls atomic progress every 100 ms, so export cannot flood its event queue.

The page uses one vertical SplitView with contextual Media and Details panels. Panels start closed and remain overlays until explicitly pinned. Pin eligibility reserves 480 logical pixels for the viewer after subtracting panel widths and gaps. Resize can unpin a panel but never pins it automatically. Layout preferences are independent of workspace contents. Their dedicated `editor-layout.ini` uses the application configuration root, including its harness override; persistence does not depend on Qt organization metadata or the registry.

Marker times are filtered to the trim range, rebased to zero, and staged with the final media filename using the shared model. Publication persists a bounded recovery journal before installing companions or replacing completed media. Existing companions are backed up, including a stale marker sidecar when no markers survive. Media rename is the commit point. Startup recovery uses native file identities to restore companions before commit or clean backups after commit. Changed or ambiguous files retain the journal and staging for investigation. A publisher lock excludes recovery during active publication. This ordering is not a filesystem-wide atomic transaction and does not prove power-loss durability. A metadata failure retains the recovery source and must not be reported as success. Sidecar paths replace the media extension: `clip.mkv` and `clip.mp4` each derive `clip.markers.json`. No chapters are written into the container.

## Audio identity and monitoring

Audio metadata carries stable track IDs, physical container mappings, names, roles, processing provenance and default monitoring. Matroska tags are authoritative only when they agree with the actual tracks and codec formats. MP4 and the WebM sidecar fallback use a sidecar bound to final file identity, length and full SHA-256 after container updates. File publication completes only after both media and identity sidecar are available; interrupted publication retains recovery artifacts.

Missing, invalid or stale metadata requires an explicit stopped-state monitoring selection. Legacy selections are bound to exact source bytes before their IDs can be reused after reopening. Preview and render consume the same immutable selection. Confirmed empty selections yield video-only render output on linked imports. For per-stream timelines the rendered mix lineage comes from the enabled clips' stream identities, not from a monitoring selection. A rendered PCM24 stereo mix receives a new track ID and records its input track/media lineage; stream copy preserves identities while updating the actual output mapping.

## Recording clip jobs and storage ownership

Recording Clip creation is unavailable in v1.3. `product::kRecordingClipsAvailable` in `app/models/RecordingCapabilities.h` is the compile-time authority. The coordinator rejects requests with `ProductCapabilityUnavailable` before consulting committed media or allocating a request, and does not construct a ClipJob worker. Confirm/cancel cannot admit work. The adapter clamps availability and rejects invokable plan/confirm/cancel calls even with stale positive state. The control policy rejects request/confirm with `unavailable`, and dormant QML controls follow the adapter's constant capability. Runtime settings cannot override it.

The following clip implementation remains compiled and directly testable. Its regression results are engineering evidence, not qualification of a shipping creation feature. Enabling it requires the inclusive 33,554,432-byte per-active-job contract, codec/long-duration decode evidence and recording/isolation qualification. That memory contract remains unresolved. Previously saved clips use normal import, History, playback and editing/export. Background index, file identity, leases, publication recovery and MP4 delivery retain their ordinary recording/editor ownership.

Recording clips consume a finite committed index snapshot and independently leased encoded source files. They do not share capture buffers, GPU surfaces, encoder contexts or the recorder's output cursor. Each lease pins the native file identity and readable extent through a separate read handle. The registry lock protects metadata only: file opening, hashing, callbacks and worker joins happen outside it. Renaming or retention cannot substitute another file behind a clip or editor reader. An editor that still needs the original path defers master renaming. Occupied media or companion destinations retain the original source rather than replacing unrelated files.

The planner finds proven closed video access and committed coverage for every track in recording time. Container keyframe flags alone are insufficient. Segment-local PTS/DTS map to a common recording origin, including negative decode timestamps and verified Opus preroll. A final boundary requires the matching successful segment seal. When an end RAP is the first picture of the next segment, the plan pins that segment solely as a boundary witness. The worker reads and verifies the witness without copying its picture or audio into the clip. It streams the finite interval through bounded extent pages and preserves actual copied source ranges in verified metadata. PCM and Opus have copy paths. AAC/FLAC and MP4 clips fail explicitly rather than entering an unqualified copy or render path.

The committed reader traverses bounded Matroska block elements directly. It rejects oversized encoded payloads before allocation and requires exact packet timestamp additions. It does not probe a live file through a decoder. The immutable descriptor supplies the validated codec and track configuration. Index validation completes before the writer opens. Selected byte extents are spooled to an exclusively owned temporary file and replayed in bounded pages, so decoder metadata does not overlap the writer packet windows. After header initialization, a writer without an index releases its configuration codec and manifest copies. The decision to emit exact audio timestamps is retained independently of those copies. Clip output streams cue entries through an exclusively owned temporary spool and retains every keyframe cue without accumulating the complete cue table in memory. Closed output is checked against its authored manifest and full content identity before publication; this check does not substitute for independent decode qualification.

When admitted through direct engineering entry points, the retained service owns one clip worker and at most three outstanding requests. Review holds source leases and storage reservations without keeping encoded payloads. Admission bounds retained marker storage and the closed-segment seal vector to 2 MiB each, including unused vector capacity. A unique private staging directory owns the attempt's output and companions. Completion follows trailer close, metadata and content-identity verification, and non-overwriting atomic publication. Failed or cancelled staging cleanup removes only files owned by that attempt. Clip errors do not alter the recorder outcome. Recording stop and clip cancellation are independent, while application teardown closes admission, cancels work and joins outside registry locks.

A shared token bucket admits index transfers, clip media and metadata I/O, and segment MP4 remux I/O at 16 MiB/s with a 4 MiB burst and maximum physical transfer. It also covers MP4 faststart's second pass. Recording payload writes remain outside this background budget. Available recorder diagnostics pause background work under critical health, disk bottlenecks, excessive queue depths or measured slow writes. Cancellation and shutdown wake blocked callers. Clip reservations use the union of selected committed byte extents, extent-spool entries and bounded output/staging overhead. Large absolute source offsets do not reserve an entire recording. Reservations also protect other outstanding clips, the primary recording safety floor and pending primary delivery storage. Packet, reorder, cluster, extent and metadata limits constrain components; they do not establish a measured aggregate memory bound or live game-frame-time qualification.

## Shutdown

Stop/wake producers before joining consumers: demux, video, then audio, with every blocking wait notified. Waits tied to another queue or clock have a bounded backstop so a missed notification cannot hang shutdown. UI/session destruction must not release a backing frame still owned by the render mailbox or a context still used by a worker.
